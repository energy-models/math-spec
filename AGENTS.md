# AGENTS.md

What a change here is held to, on top of [CONTRIBUTING.md](CONTRIBUTING.md).
Facts about this project that the tree does not show and no tool checks. A
rule a tool checks is not repeated here; the tool's message says it.

To learn what the project _is_, read [docs/](docs/index.md), and
[what counts as language](docs/about/what-counts-as-language.md) first.

`.claude/CLAUDE.md` is a symlink to this file.

## Hard rules

- **The user merges.** Merge only when told to. Never force-push. Never delete
  a branch you did not create.
- **Mark what a session wrote** at the top of every PR body, issue and comment,
  never in a footer. The intent line is the human's; never paraphrase their ask
  into a first-person "I want this because". Where they wrote none, quote the
  ask verbatim above the note. Do not reply, concede or decide as someone else.
  In the tree, nothing is marked; `Co-Authored-By` is the record.

  ```markdown
  > **Prompt:** <the ask, verbatim>

  > [!NOTE]
  > The following content was generated by AI.

  The claim, within forty words.

  <details><summary>Method, gate output, alternatives</summary>

  …

  </details>
  ```

- **No compatibility promise on the `0.0.0-alphaN` stream.** Rename, move or
  delete. No alias, deprecation cycle, `legacy_` path, or hand-written message
  for the old spelling. A test asserting the old behaviour is not a blocker;
  say in the PR where its coverage moved.
- **A breaking marker in the PR title is refused** by the
  `Conventional commit subject` check. Describe the break in the PR body.
- **Never edit a generated file by hand.** Regenerate it and read the diff.
  Generated files are the schema, the golden typesetter output, and the pages
  in the `GENERATED` table of `tests/test_docs.py`, which include the README
  and `docs/index.md`. A new generator lands with a row in that table.

  ```bash
  pixi run python -m tools.schema              # schema/mathspec.schema.json
  pixi run python -m tests.typesetting.golden  # tests/typesetting/golden/*.out
  ```

- **The version comes from the git tag.** Never write it into a file.
- **Triage a language construct before designing it**: primitive, macro, or
  refused, against [limits.md](docs/about/limits.md). Whatever the loader
  admits, the typesetter prints in all three formats.
- **Everything decidable without data is decided at load**, and the error
  names the rewrite. `tests/test_validation.py` holds messages to that.

## Environment and gates

- Prefix every command with `pixi run`.
- `pixi run lint` before every commit. `pixi run ci` before every push; it is
  `lint`, `test`, `docs-build` and `compile-tex`, and it is what CI runs.
- After a change to `pixi.toml`, run `pixi lock`. Runtime dependencies are
  mirrored in `pyproject.toml`; keep both lists in step.
- A generated page also belongs in `.prettierignore`.
- `pixi run test-coverage` is a local instrument, not a gate.

## Branch and worktree

- If not instructed differently, implement PRs from worktrees
  ```bash
  git fetch origin
  git worktree add ../wt/<topic> -b <type>/<topic> origin/main
  ```
- Branch from fetched `origin/main`, never from HEAD or a local `main`.
- Never switch the branch of the primary checkout.
- Keep the worktree out of gitignored paths: `pyrefly` skips them and exits 0.
- Share nothing between worktrees by hand. Remove the worktree when the PR
  merges.
- Check `gh pr view` before rebasing or reviving anything.
- Finished means: committed, pushed, PR open, URL reported, CI state as it
  stands. Not CI green.

## Code and tests

- **No explanatory inline comments.** Complex logic becomes a helper with a
  docstring. Inline stays: pragmas with their reason, `#:` attribute docs,
  section banners, a case label where parametrizing would distort the test,
  and a one-line justification of a line that reads as a mistake.
- **Put the claim in the message that prints.** An assertion message is
  required where the claim is not on the line: a literal collection, a count,
  a tolerance, an absence.

  ```python
  assert names == ['bus', 'snapshot', 'tech'], 'dimensions come back sorted, not in declaration order'
  ```

- **Parametrize cases, with `id` as the label.** Not five `pytest.raises` in
  one test.
- **Reproduce a bug as a failing test first.** Watch it fail on the broken
  tree. Put what was wrong in the test's docstring.
- **A guard lands with the test that fails without it.** Delete the guard,
  run the suite, put the result in the PR.
- **Docstrings.** Google form; `ruff`'s `D` rules gate `src/` and are off
  elsewhere. `D1` is off, so this decides: a public name carries what it does,
  takes, returns, how it fails, and what it guarantees, in the caller's terms.
  A private helper carries the constraint that made it exist. Where the
  signature already says what a function takes, write the one-line docstring
  and no `Args:` block. `to_spec` is the model.
- **Rationale goes in the PR, history goes in git.** Neither goes in the code.
- **A number in the tree carries a `#nnn`** to the PR of this repository that
  measured it, beside its conclusion. The method and base commit stay in that
  PR. A number the code acts on, such as a cap or a tolerance, stays inline.
  Never replace a number with a vague qualifier.
- **Simplest thing that works.** No new layer, registry or option until a
  second caller needs it. A cleanup pass ends in fewer lines and fewer
  concepts.
- **Docs move with the change.** A construct added, renamed or retired updates
  the [language reference](docs/reference/language/index.md). A change that
  moves a limit updates [limits.md](docs/about/limits.md), and says so in the
  PR. After a decision, sweep for prose that now contradicts it.

## Commit messages and PR titles

The PR title is the changelog line. It names the outcome, as a complete
lower-case sentence a changelog reader can follow. Not an activity, not a
mechanism, not `AST`, `dim` or `a pass`.

The topmost row the diff touches decides the type:

| The diff touches                                       | Type                           |
| ------------------------------------------------------ | ------------------------------ |
| `src/`                                                 | `feat` `fix` `perf` `refactor` |
| `docs/`, `examples/`, `mkdocs.yml`                     | `docs`                         |
| `tests/`                                               | `test`                         |
| `.github/`, `pixi.toml`, `pixi.lock`, `pyproject.toml` | `ci` / `build`                 |
| `AGENTS.md`, `CONTRIBUTING.md`, `tools/`, `scripts/`   | `chore`                        |

A reshuffle in `src/` that no consumer can tell apart is `chore`. A new
example or rung is `docs`. A dependency bump that changes what the package
accepts is `feat` or `fix` on that outcome.

```
yes  fix(parser): a where clause with a trailing comma loads
yes  feat(language): a coordinate may declare its own label space
no   fix(schema): fix schema bug                                  (activity)
no   fix(parser): strip the trailing token before the pyparsing pass  (mechanism)
no   feat: rung 15 — investment periods with a growth limit       (docs: by the table)
```

## PR descriptions

Claim within forty words, then evidence in `<details>`. Say which gate you
ran and what you did not run. Name what you deliberately did not do, and any
default here you departed from. One issue, one PR; stack separable work on the
base branch. Rewrite a body the work has overtaken instead of appending a
comment.

## Issues

[CONTRIBUTING.md](CONTRIBUTING.md#reporting-bugs-and-requesting-features) has
the templates. An issue body, a finding, and your own earlier analysis are
claims to re-check against the code. A body a rewrite has invalidated is
closed and re-filed, not annotated.

## Working with the user

- "Discuss", "should we" and "is it worth" are questions. Answer, then stop.
- Do not widen the scope. Name the adjacent thing in one sentence.
- Recommend; do not survey.
- "It passes" names the gate you ran and what you did not run. Check the
  user's numbers too.

## Prose

Plain declarative sentences, Simplified Technical English (ASD-STE100), in
pages, issues, PRs, commits and conversation. Documentation pages follow
[the docs-writing skill](.claude/skills/docs-writing/SKILL.md).
